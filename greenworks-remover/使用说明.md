# Greenworks 屏蔽工具 — 使用说明

一个通用的 Node.js 小工具，用于屏蔽 **RPG Maker MV / MZ** 游戏中的
Greenworks（Steamworks 集成），解决非 Steam 环境下启动报错的问题。

## 解决什么问题

部分从 Steam 打包出来的 RPG Maker 游戏自带 Steamworks 插件，脱离 Steam 直接运行时，
控制台会刷出类似错误，甚至导致插件加载中断、游戏无法进入：

```
Greenworks failed to load. Make sure you copied all files from the Steamworks SDK...
Error: Cannot find module './lib/greenworks-win64'
Uncaught ReferenceError: store is not defined   (OrangeGreenworks.js)
```

## 工具做了什么

| # | 涉及的文件 | 操作 |
|---|-----------|------|
| 1 | `www/js/plugins.js`（或 `js/plugins.js`） | **保持**所有名字含 "greenworks" 的插件为启用状态（见下方说明） |
| 2 | `www/greenworks.js` | 整个替换为无害空实现：插件加载它后初始化失败但不崩溃，自动走插件自带的无操作降级路径 |
| 3 | `www/js/plugins/OrangeGreenworks.js` | 注释掉有 bug 的 `store(e);`，消除 "store is not defined" 二次崩溃 |

**为什么不禁用插件？**
很多游戏的事件脚本会直接调用全局对象（如 `OrangeGreenworks.activateAchievement`）。
若在 plugins.js 中禁用插件，事件执行到相关脚本时会抛出
`ReferenceError: OrangeGreenworks is not defined`。因此正确做法是：
保持插件启用 + 提供空实现的 greenworks.js —— Steam 相关调用全部安全降级，
事件脚本照常运行。

- 首次修改前自动备份为同名 `*.bak` 文件；重复运行不会覆盖最初备份。
- 已打过补丁时再次运行会自动跳过（幂等）。
- 同时兼容 MV 和 MZ 的目录结构。

## 使用方法

需要已安装 [Node.js](https://nodejs.org/)（任意较新版本均可）。

### 方式一：屏蔽

把整个工具文件夹放到游戏目录里（或任意子目录），然后运行：

```powershell
node Greenworks屏蔽工具\fix-greenworks.js
```

脚本会自动向上查找游戏根目录，无需切换目录。

### 方式二：还原

想恢复原状时（例如重新打包回 Steam）：

```powershell
node Greenworks屏蔽工具\fix-greenworks.js --restore
```

### 方式三：处理其他游戏

无需复制脚本，直接指定目标游戏目录即可：

```powershell
node "本工具路径\fix-greenworks.js" "D:\games\某个RPGMaker游戏"
```

## 常见问题

**Q: 屏蔽后成就/云存档还能用吗？**
A: 不能。此工具面向脱离 Steam 运行的场景；本地存档不受影响。
   事件中的成就调用会被安全忽略，不会报错。

**Q: 如何确认生效？**
A: 启动游戏不再出现 Greenworks / store 相关报错；
   控制台仅有一条 "Greenworks failed to initialize." 属正常降级提示。

**Q: 会影响游戏本体吗？**
A: 只改动上述 3 个 JS 文件，不碰游戏数据、素材和存档；`--restore` 可完整还原。
